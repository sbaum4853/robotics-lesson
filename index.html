Quick recap

Remember last class?

1. Build 1 counted hundreds from one touch because…
Right. Build 1 counted the state, and loop() checks it thousands of times a second.
2. Build 2 counted only when the pin changed from HIGH to LOW. That moment is called…
Right. An edge is the moment of change.
3. Build 2 still sometimes counted one touch as 3 or 4. Why?
Right. That's bounce. Each bounce looks like a brand-new touch. Today we fix it.
The problem

Right now, your node cheats.

One flashlight hit might count as four. In Breach Protocol, that's a node the scoreboard can't trust.

To fix it, the node needs to know something it has never known before: how much time has passed.

The tempting fix

"Just wait a bit after each count."

The bounce is over in a few thousandths of a second. So what if the program simply paused after each count?

if (reading == LOW && lastReading == HIGH) {
  count++;
  Serial.println(count);
  delay(50);   // wait 50 ms for the bouncing to stop
}

Try it if you want. It mostly works! But we're not going to use it. Next slide: why.

Why delay() is a trap

delay() puts the chip to sleep.

50 milliseconds sounds tiny. But a game node has a lot to do at the same time: watch its sensor, run its countdown, flash its LED, and soon, send messages to the Raspberry Pi. A node can't take naps.

We need a way to wait without stopping. That means using a clock.
Meet millis()

The ESP32 has a stopwatch.

From the moment it powers on, the ESP32 counts milliseconds (thousandths of a second). millis() tells you the count right now.

The stopwatch trick

Now minus then = how long

You can't ask the ESP32 "how long has it been?" But you can do what you'd do with a clock on the wall:

1
When something happens, write down the time. Save millis() in a variable.
2
Later, subtract: millis() - savedTime is how many milliseconds have passed.
3
Compare that to a limit: if (millis() - savedTime > 50) means "if more than 50 ms have passed."
The chip never stops to wait. Every time through loop() it glances at the clock and asks "has it been long enough yet?" Usually the answer is "not yet," and it goes on doing its other jobs.
New variable type

unsigned long: a box for big numbers

Time values get big fast. After one day, millis() is 86,400,000. So we store times in an unsigned long:

TypeWhat it holds
intWhole numbers, positive or negative. Fine for counts.
unsigned longVery big whole numbers that are never negative. "Unsigned" means no minus sign. Use it for anything that holds a millis() time.
The fix

Wait for the wire to go quiet.

Every time the reading changes, restart a stopwatch. Only when the reading has stayed the same for 50 ms do we believe it. All the bouncing keeps restarting the stopwatch, so it never sneaks through.

Like waiting for a bouncing ball to stop before you say where it landed. This is called debouncing.
Build 2 · the debounced counter

A node that counts honestly

const int buttonPin = 26;
const unsigned long debounceMs = 50;   // how long the pin must stay quiet

int count = 0;
int lastReading = HIGH;               // raw reading last time through loop()
int stableState = HIGH;               // the reading we BELIEVE
unsigned long lastChangeTime = 0;     // when the raw reading last changed

void setup() {
  Serial.begin(115200);
  pinMode(buttonPin, INPUT_PULLUP);
}

void loop() {
  int reading = digitalRead(buttonPin);

  if (reading != lastReading) {        // it changed (maybe a bounce)
    lastChangeTime = millis();         // restart the stopwatch
  }

  if (millis() - lastChangeTime > debounceMs) {   // quiet for 50 ms
    if (reading != stableState) {                 // and it's a real change
      stableState = reading;
      if (stableState == LOW) {                   // a real touch began
        count++;
        Serial.println(count);
      }
    }
  }

  lastReading = reading;
}
Build 2 · line by line

What's new

CodeWhat it means
reading != lastReading!= means "is not equal to." True whenever the raw pin changed, bounce or not.

millis() - lastChangeTime > debounceMsHas the pin been quiet for more than 50 ms?
stableStateThe reading we actually believe. It only changes after 50 quiet milliseconds.
if (stableState == LOW)The believed reading just became LOW, so a real touch began. Count it.
Notice: there's no delay() anywhere. The chip never stops watching.

Build 3 · the node's first heartbeat

Make it a game.

Time to build the core of Breach Protocol on your own breadboard:

1
At a random moment, the node's LED turns red. A signal is attacking.
2
You have 1.5 seconds to "hit" it: touch the wire to ground.
3
In time: BLOCKED, and it tells you your reaction time. Too slow: ESCAPED into an Antcar.

The countdown is millis(). The hit is your debounced edge. You already know both pieces.

Step by step

Keep your yellow wire on 26 and your black wire to the blue rail from last class. Unplug USB while you wire.

Why the resistor? Without it, too much current rushes through the LED and can burn out the LED or the pin. The resistor limits the current. It can go on either side of the LED; the current is the same anywhere in a single loop.

Build 3 · the code

The reaction timer

const int buttonPin = 26;
const int ledPin = 23;
const unsigned long debounceMs = 50;
const unsigned long windowMs = 1500;   // time you get to hit the node

// debounce memory (same idea as Build 2)
int lastReading = HIGH;
int stableState = HIGH;
unsigned long lastChangeTime = 0;

// game memory
bool armed = false;                // is a signal attacking right now?
unsigned long nextAttackTime = 0;  // when the next attack starts
unsigned long armedTime = 0;       // when the current attack started
int blocked = 0;
int escaped = 0;

// Returns true ONCE, at the start of each real touch
bool hitDetected() {
  int reading = digitalRead(buttonPin);
  bool hit = false;
  if (reading != lastReading) {
    lastChangeTime = millis();
  }
  if (millis() - lastChangeTime > debounceMs && reading != stableState) {
    stableState = reading;
    if (stableState == LOW) {
      hit = true;
    }
  }
  lastReading = reading;
  return hit;
}

void setup() {
  Serial.begin(115200);
  pinMode(buttonPin, INPUT_PULLUP);
  pinMode(ledPin, OUTPUT);
  randomSeed(esp_random());
  nextAttackTime = millis() + random(2000, 5000);
  Serial.println("Node online. Defend it!");
}

void loop() {
  bool hit = hitDetected();
  unsigned long now = millis();

  // 1. Time for an attack?
  if (!armed && now >= nextAttackTime) {
    armed = true;
    armedTime = now;
    digitalWrite(ledPin, HIGH);
    Serial.println("!!! NODE UNDER ATTACK !!!");
  }

  // 2. Hit in time?
  if (armed && hit) {
    armed = false;
    digitalWrite(ledPin, LOW);
    blocked++;
    Serial.print("BLOCKED in ");
    Serial.print(now - armedTime);
    Serial.println(" ms");
    nextAttackTime = now + random(2000, 5000);
  }

  // 3. Too slow?
  if (armed && now - armedTime > windowMs) {
    armed = false;
    digitalWrite(ledPin, LOW);
    escaped++;
    Serial.println("ESCAPED into an Antcar!");
    nextAttackTime = now + random(2000, 5000);
  }
}
Build 3 · how it works

The node has two moods.

The variable armed is a bool: it can only be true or false. It remembers which mood the node is in. Every pass through loop() asks three quick questions (attack time? hit? too slow?) and then moves on. No waiting, ever.

New codeWhat it does
bool hitDetected() { … }Your Build 2 debounce, packed into a function that answers true once per real touch.
random(2000, 5000)A random number from 2000 up to 4999, so attacks come 2–5 seconds apart.
randomSeed(esp_random());Shuffles the random numbers so the pattern is different every time the board starts.
!armed! means "not." Read it as "not armed."
